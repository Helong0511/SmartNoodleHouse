# 人脸识别说明

到店迎宾仅匹配**已主动授权**会员的加密特征向量，不做陌生人人脸检索。

迎宾语模板、称呼占位符、口味/餐品智能推荐见：[人脸迎宾与智能推荐](./人脸迎宾与智能推荐.md)。

## 2. 摄像头接入（DS-2CD3347SWDV3-LT）

### 2.1 海康 RTSP 路径

| 通道 | 路径 | 用途 |
|---|---|---|
| 主码流 | `/Streaming/Channels/101` | 预览更清晰，CPU 占用高 |
| 子码流 | `/Streaming/Channels/102` | **识别推荐**；画质够用、更省 CPU |

完整示例（密码中的特殊字符需 URL 编码，或把账号密码填到后台独立字段，见下节）：

```text
rtsp://admin:密码@192.168.1.101:554/Streaming/Channels/102
```

默认管理账号多为 `admin`；首次上电请在摄像头 Web 改强密码。

### 2.2 连通性自检

**场景：本地调试（Windows PowerShell）或生产（Ubuntu bash）** 均可：

```bash
ffprobe -rtsp_transport tcp "rtsp://admin:密码@192.168.1.101:554/Streaming/Channels/102"
```

能正常输出流信息即可。拉流失败时依次查：同网段、账号密码、554 端口、防火墙、是否误用公网地址。

### 2.3 后台添加摄像头

路径：**迎宾 → 摄像头**（`/cameras`）。

| 字段 | 填写建议（本型号） |
|---|---|
| 名称 | 如「门口迎宾」 |
| 地址 `source_url` | `rtsp://192.168.1.101:554/Streaming/Channels/102`（**URL 内不要带明文密码**） |
| 用户名 | `admin`（或你改过的账号） |
| 密码 | 摄像头密码（入库加密存储） |
| 识别帧率 `detect_fps` | **2～3**（单店 1～2 路足够；过高易打满 CPU） |
| 门店 | 绑定对应门店 |

说明：

- 密码填在「密码」字段，由后端加密保存；禁止把 `rtsp://user:pass@...` 明文长期留在地址栏。
- USB 调试摄像头可将地址填 `0`（仅本地联调，不适合门店正式多路）。
- Nginx 默认对 `/api/cameras/` 预览流做内网限制；公网访问被 deny 属预期。

### 2.4 服务端进程要求

识别只在拿到 Redis Leader 锁的进程上跑：

| 配置 | 要求 |
|---|---|
| `PROCESS_ROLE` | `auto` 或 `leader`（纯 API worker 不采流） |
| `ENABLE_RECOGNITION_WORKER` | `1` |
| 部署位置 | 摄像头与识别进程宜在**店内或同内网**；云端副本勿直接拉店内 RTSP |

## 3. 授权与采集（小程序）

- 入口：小程序摄像头实拍 → `POST /api/miniprogram/face/consent` 或 `face/consent-base64`。
- **禁止**客户端上传 `embedding` / `feature_vector`；服务端用 InsightFace（512 维）提取。
- 维度不匹配 **fail-closed**（禁止截断 / padding）。
- 质量门控：清晰度、人脸占比；活体为 **basic anti-spoof**（清晰度 / 亮度 / 姿态粗检），**不是**真活体 SDK。API 字段 `anti_spoof_level=basic`。
- 顾客须已开启人脸迎宾同意；未授权会员不会被匹配迎宾。

---

## 4. 匹配与迎宾

- 阈值：`FACE_MATCH_THRESHOLD` 与后台 `system_settings.face_match_threshold`（门店可覆盖）。
- 多帧确认：`FACE_CONFIRM_FRAMES` / `face_confirm_frames`。
- 冷却：`WELCOME_COOLDOWN_SECONDS`（Redis 原子抢占）。
- 识别 worker：抢到 Redis Leader 锁的进程（`PROCESS_ROLE=auto|leader`）且 `ENABLE_RECOGNITION_WORKER=1`；向量走 `FaceEmbeddingCache` 按 `updated_at` 增量刷新。
- 触发后：拼迎宾语 → TTS → 写 `welcome_logs` → WebSocket 推送「迎宾日志」。
- **摄像头播放迎宾语音**（后台「迎宾与人脸」开关 `camera_speaker_tts_enabled`，可按店，改完即时生效、无需改 `.env`）：开启后按 `TTS_PROVIDER` 合成 WAV（生产推荐 `edge`+`gentle_female` 神经女声，需出网与 ffmpeg），经海康 ISAPI `TwoWayAudio` 推到触发识别的摄像头扬声器（对讲型机，如 DS-2CD3347SWDV3-LT）；关闭或推流失败则回退本机扬声器（Windows SAPI / Linux espeak）。

话术与 `{称呼}` / `{口味}` / `{餐品}` 等占位符见：[人脸迎宾与智能推荐](./人脸迎宾与智能推荐.md)。

## 5. 安全与隐私

- 特征密文：`FACE_ENCRYPTION_KEY`（Fernet）；轮换后旧密文可能无法解密，需重采。
- 访客事件 `visitor_events` 有保留期，不含身份 embedding。
- 摄像头 RTSP / 管理页 **仅店内网**；勿对公网开放预览与 554 端口。
- SSRF 防护：摄像头 URL 禁止指向元数据、回环、链路本地等危险地址（见 `camera_credentials.assert_camera_url_safe`）。

| 配置 | 说明 |
|---|---|
| `FACE_ENCRYPTION_KEY` | 人脸特征向量加密密钥 |

## 7. 常见问题（本型号）

| 现象 | 处理 |
|---|---|
| 摄像头 OFFLINE | 同网段、固定 IP、账号密码、`ffprobe` 测 102 通道；确认 Leader 在跑识别 |
| 预览 403 | 公网访问被 Nginx deny，属预期；请从店内网或 VPN 看 |
| CPU 偏高 | `detect_fps` 降到 2；用 **102 子码流**；多 worker 时仅 1 个 Leader 采流 |
| 认不出人 | 检查是否已小程序授权；调低 `face_match_threshold` 需谨慎误识；改善安装角度与逆光 |
| 误迎宾 / 重复迎宾 | 提高阈值或 `welcome_cooldown_seconds`；确认多帧确认已开启 |
| 密码特殊字符拉流失败 | 密码改填后台「密码」字段，地址用不含账密的 `rtsp://IP:554/...` |
