## 使用说明

**推荐做法**：把本文件作为提示词一次性粘贴，让 AI 按 P0 → P1 → P2 顺序执行。

**若上下文超限**：按阶段拆成 3 次对话，每次只粘一个章节（第一章 / 第二章 / 第三章），并附上通用约束段落。

**通用约束段落**（如果分段执行，每次都要带上）：

```

1. 只改我明确指定的文件和代码，不要顺手重构无关代码。

```

## 全局常识（避免改错方向）

这个项目里有几处**看起来可疑但实际上是刻意为之的设计**，修改时**不要动它们**：

| 位置 | 现象 | 为什么不能动 |
| --- | --- | --- |
| `utils/context.js:341-389` `refreshTableBinding` | 网络失败时返回 `{ok:false, token}` 而非清空 token | 这是为了区分「服务端判定失效」与「网络不可达」，是修复「真机反复要求扫码绑桌」的关键。清掉会复现该 Bug |
| `utils/api.js:190-192` | 只有 GET 才自动重试 | 防止 POST 重试造成重复下单 |
| `packageOrder/confirm/confirm.js:919-945` | 幂等键 = 内容哈希 + nonce（不是纯 UUID） | 纯 UUID 会失去重试幂等性，纯哈希会让「同款再买」命中已付订单 |
| `packageOrder/confirm/confirm.wxml:17` | 前端算的金额只作展示 | 真实金额由服务端重算，前端不承担裁决 |
| `utils/cart.js:176-179` | `!p` 时要看 `complete` 才判定下架 | 防止菜单分页没拉全时整单被判失效变 0 元 |
| `utils/media.js:100-116` `mapPool` | 限制 4 路并发下载 | 微信 HTTP 连接池只有 10 路，不限制会把菜单接口挤超时 |

const appSrc = read('app.js')
if (/remoteLogger\.install\(\)/.test(appSrc) && !/isRelease\(\)/.test(appSrc)) {

  process.exit(0)
}

console.log('❌ 上传前有 ' + problems.length + ' 项待处理：\n')
problems.forEach((p, i) => console.log(`${i + 1}. ${p}`))

## P1-3 支付签名类型静默兜底

**文件**：`utils/pay.js`
**严重性**：🟠 参数缺失时静默兜底 `'RSA'`，若后端实际用 `MD5` 会直接支付失败且不报明确错误

### 改动前（第 78-99 行）

```js
    const { timeStamp, nonceStr, package: pkg, paySign, signType } = payData
    if (!timeStamp || !nonceStr || !pkg || !paySign) {
      reject(new Error('支付参数不完整，请确认已配置微信支付'))
      return
    }
    wx.requestPayment({
      timeStamp: String(timeStamp),
      nonceStr,
      package: pkg,
      signType: signType || 'RSA',
      paySign,
      success: (res) => resolve({ ok: true, res, payData }),
      fail: (err) => {
        const msg = (err && err.errMsg) || '支付已取消'
        const cancel = /cancel/i.test(msg)
        const e = new Error(cancel ? '您已取消支付' : msg)
        e.payCancel = cancel
        e.payUncertain = !cancel
        e.payData = payData
        reject(e)
      }
    })
```

### 改动后

```js
    const { timeStamp, nonceStr, package: pkg, paySign, signType } = payData
    if (!timeStamp || !nonceStr || !pkg || !paySign) {
      reject(new Error('支付参数不完整，请确认已配置微信支付'))
      return
    }
    // signType 必须由后端显式下发：微信支付签名算法可能是 MD5 或 HMAC-SHA256，
    // 静默兜底成 RSA 会让「后端漏传 + 实际用 MD5」的组合直接调起失败，
    // 且错误信息不会指向根因。宁可在这里明确报错，也不猜。
    if (!signType) {
      reject(new Error('支付参数缺少 signType（signType 须由后端下发，不可省略）'))
      return
    }
    wx.requestPayment({
      timeStamp: String(timeStamp),
      nonceStr,
      package: pkg,
      signType,
      paySign,
      success: (res) => resolve({ ok: true, res, payData }),
      fail: (err) => {
        const msg = (err && err.errMsg) || '支付已取消'
        const cancel = /cancel/i.test(msg)
        const e = new Error(cancel ? '您已取消支付' : msg)
        e.payCancel = cancel
        e.payUncertain = !cancel
        e.payData = payData
        reject(e)
      }
    })
```

这个改动会让**后端漏传 `signType` 的情况下支付直接失败**（而不是像现在这样可能侥幸成功）。

请先帮我确认：**后端 `POST /payments/orders/{id}/pay` 返回体里到底有没有 `signType` 字段？**

- 如果有 → 放心改
- 如果没有，但实际签名用的是 `MD5` → 先改后端补上 `signType: 'MD5'`，再改这里
- 如果没有，且你希望先保持现状 → 告诉我，我把这项改成「只加日志警告，不改行为」

**不要在不确认的情况下直接改。**

## P2-4 购物车列表 `wx:key` 用了 `index`

**文件**：`pages/menu/menu.wxml`

### 改动前（第 120 行）

```html
      <view class="cart-item {{item.invalid ? 'invalid' : ''}}" wx:for="{{cart}}" wx:key="index">
```

### 改动后

```html
      <view class="cart-item {{item.invalid ? 'invalid' : ''}}" wx:for="{{cart}}" wx:key="cartKey">
```

### ⚠️ 这项不能只改 WXML

用 `wx:key="cartKey"` 要求每个 cart item 上有一个**唯一且稳定**的 `cartKey` 字段。购物车的唯一标识是「商品 ID + 规格 ID 组合」（见 `utils/cart.js:133-136` 的 `itemKey`）。

所以需要在 `packages/menu/menu.js` 的 `refreshCartBar()` 里给每项补上 `cartKey`。

在 `packages/menu/menu.js` 中找到 `refreshCartBar`（第 232-281 行），**改动前**：

```js
    const { list, invalidCount } = cartUtil.reconcileWithProducts(rawCart, products, categories, { complete })
    const cart = list.map((raw) => {
      const item = cartUtil.normalizeItem({ ...raw })
      return {
        ...item,
        imageUrl: media.resolveUrl(item.main_image || item.imageUrl || '')
      }
    })
```

**改动后**：

```js
    const { list, invalidCount } = cartUtil.reconcileWithProducts(rawCart, products, categories, { complete })
    const cart = list.map((raw) => {
      const item = cartUtil.normalizeItem({ ...raw })
      return {
        ...item,
        // wx:key 需要稳定唯一值：商品 ID + 排序后的规格 ID（与 cartUtil.itemKey 同源规则）。
        // 不能用 index —— 删除中间项时会让后续项复用错误的节点，导致数量/规格显示错位。
        cartKey: `${item.product_id}:${(item.option_ids || []).slice().sort((a, b) => a - b).join(',')}`,
        imageUrl: media.resolveUrl(item.main_image || item.imageUrl || '')
      }
    })
```

### ⚠️ 一个必须验证的边界情况

如果**同一商品 + 同一规格**在购物车里可能出现两条记录（理论上 `mergeCartItem` 会合并，正常不会），那么 `cartKey` 会重复，反而比 `index` 更糟。

请帮我确认：`utils/cart.js` 的 `mergeCartItem`（第 139-156 行）是否保证了「同商品同规格只有一条」？

- 如果保证 → 放心改
- 如果不保证 → 用 `cartKey: `${...}_${index}`` 兜底（牺牲部分复用优化，但保证不出错）

**先确认再改。**
