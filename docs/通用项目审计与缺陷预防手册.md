# 通用软件项目审计与缺陷预防手册

> 目标：把本项目审计发现的风险类型沉淀为其他项目可复用的工程标准。适用于 Web/API、移动端/小程序、SaaS、多租户、支付订单、IoT、后台管理、单体和微服务。
> 原则：以真实代码、真实配置、真实测试为证据；本文是通用检查框架，不代表本仓库每项能力均已实现。使用时必须标记适用性、证据、负责人和验证结果。

## 1. 审计总原则

1. 先记录仓库、分支、commit SHA、工作区、技术栈、部署拓扑、数据库、缓存、外部平台和运行时基线。
2. 代码、配置、CI、迁移、模型、API、文档互相核对；冲突记差异，不猜测。
3. 风险优先：资金、认证授权、租户隔离、数据丢失、密钥泄漏优先于体验和代码风格。
4. 每项问题形成闭环：证据/复现 → 根因 → 最小修复 → 回归测试 → 提交 → 文档。
5. 不删除失败测试、不放宽断言、不跳过关键 CI 来制造绿灯。
6. 不盲目追新：依赖版本必须兼容运行时、平台、ABI、驱动和框架；锁文件保证可复现。
7. 生产默认安全：拒绝弱凭据、Mock、调试模式、开放管理端口和不安全回退。
8. 新项目只有在确有存量兼容需求时才保留旧实现；否则采用单一规范，避免无意义双轨。
9. 文档和源码统一 UTF-8；示例凭据必须是明显虚构的占位符。
10. 每次变更绑定 commit、PR、测试环境、命令、结果、未覆盖范围和外部阻塞。

## 2. 仓库与环境基线

- [ ] 确认 owner/repo、默认分支、保护规则、commit SHA、工作区状态。
- [ ] 列出本地/远端分支、PR 和未合并提交；逐文件比较后再清理分支。
- [ ] 备份未提交修改、未跟踪文件、数据库快照和必要配置；保护备份权限。
- [ ] 检查 .env、证书、私钥、数据库导出、日志、上传文件是否被 Git 跟踪或打包。
- [ ] 扫描排除 node_modules、venv、.venv、target、dist、缓存和生成文件。
- [ ] 记录 OS、CPU/内存、语言运行时、包管理器、数据库、Redis、浏览器/小程序版本。
- [ ] 核验 .gitignore、构建上下文、发布产物和敏感文件排除规则。
- [ ] 只检查环境变量名称、是否设置、格式和安全策略；禁止输出真实值。

## 3. 依赖与供应链

- [ ] 找出每个独立子项目的 manifest 和 lockfile，不能只检查仓库根目录。
- [ ] 每个直接依赖对应真实 import、插件、CLI、构建配置或动态加载。
- [ ] 测试/开发依赖与生产依赖分组；未使用依赖删除前先核查反射、动态导入和插件发现。
- [ ] 区分重复直接声明、重复源码 import、传递依赖多版本和 npm dedupe；不能把依赖树重复误报为源码重复。
- [ ] 使用干净安装和锁定模式：npm ci、pip 哈希锁安装、cargo --locked 等。
- [ ] 版本来源优先官方发行页、官方文档、官方 Registry、RustSec、OSV、GitHub Security Advisories。
- [ ] 记录审计日期、锁定版本、稳定版、支持周期、最低运行时、平台 wheel/ABI 和升级理由。
- [ ] 升级前阅读 breaking changes、弃用和安全公告；不因“最新”盲升主版本。
- [ ] 不直接执行 npm audit fix --force；逐项评估传递依赖影响。
- [ ] 本地和 CI 运行时版本一致或有明确矩阵；对 Windows/Linux、架构、驱动分别验证。
- [ ] 检查循环依赖、大小写路径、隐式动态依赖和同一职责的多套实现。

## 4. 身份认证、授权和租户隔离

- [ ] 认证与授权分离；登录成功不代表可访问任意资源。
- [ ] 服务端检查角色、权限码、资源归属和状态；前端隐藏按钮不是安全措施。
- [ ] 每个租户/门店读取、更新、删除、导出、统计、异步任务、WebSocket、缓存和文件访问均带租户边界。
- [ ] 不信任客户端传来的 tenant_id/store_id/user_id；从认证主体和服务端资源关系解析。
- [ ] 对列表、详情、批量、搜索、报表、导出和关联资源做跨租户负向测试。
- [ ] 总部默认与租户覆盖规则定义业务键、优先级、并行资源类型和唯一约束。
- [ ] 敏感操作实行最小权限、审批/二次确认和审计日志。
- [ ] JWT/会话检查 issuer、audience、签名算法、过期、撤销和密钥轮换。
- [ ] WebSocket 握手、订阅频道、消息推送同样验证身份、租户和权限。
- [ ] 上传、下载、对象存储和静态文件防止 IDOR、路径穿越和越权读取。

## 5. 数据库、迁移和字符集

- [ ] 明确唯一数据库真源、支持版本和生产/CI/开发方言；SQLite mock 不能代替生产数据库集成测试。
- [ ] 明确初始化 SQL、迁移工具、模型和 schema 文档的权威关系。
- [ ] 空库初始化、现有库升级、必要回滚路径均实际演练。
- [ ] 外键、唯一/检查约束、索引、默认值、NULL 语义和删除策略符合业务规则。
- [ ] 金额用 DECIMAL 或整数最小货币单位，禁止浮点金额计算。
- [ ] 明确时间存储时区、展示时区和夏令时策略。
- [ ] MySQL 全链路 utf8mb4；连接、表、列、迁移、导入导出、HTTP JSON 均检查 UTF-8。
- [ ] 测试中文、emoji、排序规则、大小写、唯一索引和乱码/双重编码。
- [ ] 生产脚本禁止意外 DROP/TRUNCATE；测试清理只针对隔离库。
- [ ] 大表变更评估锁表、在线 DDL、索引、回填批次和回滚。
- [ ] 定义归档、分区、保留期限、删除请求、备份和恢复流程。

## 6. Redis、缓存和分布式并发

### 缓存
- [ ] 缓存键包含租户/门店、资源和必要的权限/版本维度。
- [ ] TTL 加随机抖动，防止大量 key 同时过期引发雪崩。
- [ ] 热点 key 使用 single-flight、互斥重建、逻辑过期或预热，防止击穿。
- [ ] 参数校验、短 TTL 空值缓存、布隆过滤器（适用时）防止穿透。
- [ ] 数据库事务提交、缓存失效和消息事件顺序明确。
- [ ] 缓存故障按业务风险分级；支付、权限、幂等、库存不能静默绕过安全控制。
- [ ] 负缓存和热点缓存有容量上限、淘汰与清理策略。

### 锁、限流和任务
- [ ] 分布式锁使用唯一 owner token，原子校验释放；有 TTL、续租和崩溃恢复。
- [ ] 锁过期后旧持有者不得继续写；关键写使用 fencing token/epoch 或数据库条件更新。
- [ ] Redis 锁不是数据库事务替代品；最终不变量由数据库唯一约束、条件更新和幂等保障。
- [ ] 限流按 IP、用户、租户、接口等维度组合；仅信任明确配置的代理 IP。
- [ ] 明确 Redis 故障时 fail-open/fail-closed；认证、支付、验证码等敏感路径需安全降级。
- [ ] Lua、事务、pipeline 检查原子性、超时、重试和 Cluster slot。
- [ ] 重要事件不依赖 Pub/Sub 保证送达；采用持久化队列或 outbox/inbox。
- [ ] 多实例定时任务采用 leader/租约/可靠队列；进程内锁无法防止跨实例重复。
- [ ] 任务支持心跳、超时回收、幂等、死信、人工重放和审计。

### 故障演练
- [ ] Redis 宕机、主从切换、网络分区、慢查询、内存淘汰、连接池耗尽、超时和恢复均测试。
- [ ] 检查重连风暴、重试放大、队列积压、缓存重建并发和恢复瞬时流量。
- [ ] 配置连接池上限、超时、退避+jitter、熔断、隔离和指标。

## 7. 订单、支付、退款、库存和账务

- [ ] 服务端计算价格、优惠、税费、运费、库存和应付金额。
- [ ] 订单状态机明确合法迁移，禁止客户端任意传状态。
- [ ] 下单、支付、回调、退款、取消具备幂等键和数据库唯一约束。
- [ ] 支付回调先验签、校验商户/应用/金额/币种/订单号，再原子更新状态。
- [ ] 处理回调重复、乱序、延迟、主动查单、部分支付、组合支付和部分退款。
- [ ] 支付、订单、积分、券、库存、账本和通知使用事务/outbox 或可恢复 Saga。
- [ ] 累计退款不超过可退余额；并发退款用行锁/条件更新/唯一约束。
- [ ] 库存扣减原子化，取消/退款回补幂等。
- [ ] 财务账本保留原始流水；冲正新增分录，不静默覆盖。
- [ ] 渠道账单对账、漏单、重复单和差异有监控与人工处理。
- [ ] 覆盖金额边界、精度、舍入、时区和未知支付结果。

## 8. API、Webhook、消息和文件

- [ ] API schema 校验长度、范围、枚举、嵌套和上传大小。
- [ ] 输出不泄漏密码哈希、令牌、内部异常、敏感个人信息和跨租户数据。
- [ ] 外部 API 有超时、限流、分页上限、统一错误码和契约。
- [ ] Webhook 验签、时间戳/nonce 防重放、来源校验、幂等落库、快速应答、异步消费、重试和死信齐备。
- [ ] 第三方错误分类；重试遵循幂等语义。
- [ ] 上传校验 MIME、文件签名、大小、路径；避免拼接用户路径。
- [ ] 日志脱敏手机号、支付数据、访问令牌、人脸模板和密钥，并设置保留期限。

## 9. 客户端、小程序和隐私

- [ ] 客户端不保存长期高权限密钥；开发/测试/生产配置分离。
- [ ] 小程序合法域名、HTTPS、隐私声明、授权和平台审核逐项验收。
- [ ] 微信/支付宝分别做真实平台构建和登录/支付/隐私测试。
- [ ] 扫码参数不直接信任门店/桌号；服务端解析不可预测 token。
- [ ] 支付按钮防重复；返回、断网、取消、结果未知可恢复订单状态。
- [ ] 前端路由权限仅是 UX，服务端接口独立授权。
- [ ] 检查包体积、懒加载、XSS、CSP、source map 和依赖漏洞。
- [ ] 构建 warning 分类记录；warning 不等于失败，但不能无视性能风险。
- [ ] 人脸、声纹、定位、支付信息默认最少采集；主动授权、撤回、加密、审计和删除机制齐备。
- [ ] 语音播报不得公开泄露敏感信息，并提供关闭和误识别纠正。

## 10. 测试和 CI

- [ ] 单测覆盖边界、异常和状态机。
- [ ] 集成测试使用真实目标数据库/Redis/队列，不能只靠 mock。
- [ ] API 契约、端到端、双端小程序、浏览器、Windows/Linux 构建有适用测试。
- [ ] 负向测试覆盖越权、跨租户、重放、重复回调、并发、超时、缓存故障。
- [ ] 并发测试断言最终数据不变量，而非仅 HTTP 200。
- [ ] CI 包含格式/lint、类型、锁文件一致性、安全审计、单测、集成、构建和迁移测试。
- [ ] 长 job 有超时和日志；区分慢测试、死锁、网络等待和资源泄漏。
- [ ] 报告绑定 commit SHA、平台、版本、执行时间、总数、通过/失败/跳过和跳过原因。
- [ ] 不得把历史测试数字当作当前 commit 的测试结果。

## 11. 部署、运维和灾备

- [ ] 生产禁用开发账号、Mock、debug、reload 和调试接口。
- [ ] 只暴露必要端口；数据库、Redis、摄像头和管理接口不直接暴露公网。
- [ ] HTTPS、反代、可信代理、请求体限制、WebSocket、安全头和限流配置齐备。
- [ ] 服务使用非 root 用户，具备重启策略、资源限制、日志和优雅退出。
- [ ] 备份加密、异地保存、保留策略、恢复演练和 RPO/RTO 明确。
- [ ] 发布有预生产验证、迁移检查、灰度/窗口、回滚预案和发布后冒烟。
- [ ] 监控错误率、延迟、吞吐、队列、缓存、数据库连接、磁盘和外部平台失败。
- [ ] 告警有负责人、升级路径和故障手册。

## 12. 文档、编码和维护

- [ ] README、架构、开发、配置、数据库、API、部署、运维、安全、测试互相链接。
- [ ] 文档技术栈、命令、端口、路径、变量、权限码和表名与代码一致。
- [ ] 标记已实现/部分实现/规划中/外部阻塞/已废弃，不能把计划写成现状。
- [ ] 文档不含真实 token、密码、私钥、个人信息和历史绝对路径。
- [ ] 删除过期版本、错误数据库类型、旧测试数字和失效链接。
- [ ] 命令标注目标 shell；Windows PowerShell 与 Bash 分开。
- [ ] 注释解释业务不变量、并发边界、安全约束，不写无意义逐行翻译。
- [ ] 中文源码/文档统一 UTF-8，检查乱码、BOM、换行和文件名大小写。

## 13. 上线门禁

以下任一项失败，不得宣称可上线：P0/P1 未关闭；真实密钥泄漏；生产弱口令/Mock/debug；迁移/备份恢复未验证；租户越权测试失败；Redis/DB 故障关键路径无定义；必需 CI 失败或跳过；目标平台构建失败；外部平台未沙箱验证却宣称完整；没有回滚、告警和故障响应。

## 14. 问题台账与关闭标准

每项记录 ID、优先级、证据（路径/函数/行号/日志/commit）、触发条件、影响、根因、修复方案、测试命令与结果、状态、责任人、日期、关联文档。

优先级：P0 资金/安全/数据破坏；P1 核心业务/一致性；P2 稳定性/性能；P3 体验/文档。

状态：待确认、待修复、修复中、待验证、已验证、外部阻塞、风险接受。

**关闭条件：代码提交 + 对应测试通过 + 回归范围明确 + 文档更新 + 证据可追溯。**仅合并、仅 CI 绿灯或口头确认都不算闭环。

## 15. 从本项目审计归纳出的典型误区

- npm 依赖树中出现可选依赖未安装，不必然是故障；要确认是否被项目实际调用。
- 传递依赖多版本不等于源码重复 import；需要结合直接依赖和源码扫描。
- 本地 Node/npm 与 CI pin 不一致会造成环境漂移。
- 构建成功但出现大 chunk warning 是性能优化项，不是构建失败。
- SQLite 测试通过不能证明 MySQL 迁移、锁、索引和排序规则正确。
- Redis 可连接不代表 Redis 故障时安全；必须测穿透、击穿、雪崩、锁过期和恢复。
- git fetch --prune 只清理本地已失效 tracking refs，不会删除 GitHub 远端分支。
- SQL 文件有重复表定义时不能简单拼接；要核对 canonical schema、迁移基线、外键和唯一索引。
- node_modules、target、venv、dist 不应混入自有源码扫描结论。
- 历史测试报告必须标注 commit 和时间，不能冒充当前 main 实时结果。

## 16. 新项目复用步骤

1. 复制本手册和上线清单模板。
2. 首周完成仓库、数据流、威胁模型、依赖、部署基线。
3. 设计评审完成数据库、租户边界、权限、支付/任务状态机和故障策略。
4. 每个 PR 检查本手册适用项；安全和数据一致性需重点审查。
5. 每次发布执行上线门禁。
6. 每次事故回填根因、检测缺口、测试和规范改进。
7. 通用规范与项目特有实现分开，不照搬不适用技术选型。
