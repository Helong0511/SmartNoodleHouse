## 0. 执行摘要

本轮把两端 250 个文件全部读完，得到三个层次的结果：

1. **工程骨架是健康的**：101 个 JS 文件全部通过 `node --check`；309 个 `require()` 全部可解析；32 个注册页面的四件套零缺失；18 处 `usingComponents` 全部有效；`setInterval` 4 处全部有 `clearInterval` 配对；主包 5 个页面是 7~13 行的纯重定向壳，下单/支付/结果链路唯一走 `packageOrder` 分包，**不存在两套业务逻辑分叉**。

## 3. P0 —— 发布阻断与隐私合规（4 组）

### P0-1 两端 `PROD_API_BASE` 占位符 + 模块顶层求值 → 正式版启动白屏

`config/env.js:22` 两端均为 `const PROD_API_BASE = 'https://your-domain.com/api'`；`:90-95`（支付宝 `:88-93`）在 release 分支检测到占位符即 `throw`。

关键在**调用位置**：`app.js:15` `apiBase: resolveApiBase()` 位于 `App({...})` 对象字面量；`utils/api.js:4` `const DEFAULT_API_BASE = resolveApiBase()` 在模块加载期执行，且由 `app.js:4 → auth.js:1 → api.js` 在 App 注册前触发。**两处都无 try/catch** → release 下 `App()` 尚未注册就抛异常，小程序**白屏**，而不是 `env.js:21` 注释、`config/环境说明.txt`、`preflight-check.js:18` 所说的「全部请求失败」。

`getEnvDebugInfo()`（微信 `env.js:103-110` / 支付宝 `:101-108`）内部再次调用 `resolveApiBase()`，是第二条崩溃路径，被 `auth.js:111`、`context.js:389/489/496`、`pay.js` 间接引用。

**修复**：发布前替换真实 HTTPS 域名并把 `project.config.json:11 urlCheck` 改为 true；把校验延迟到首次请求；`resolveApiBase()` 顶层改为惰性求值，抛错收敛到单一入口；`preflight-check.js` 的说法改为「启动白屏」并接入上传钩子（见 P1-17）。

### P0-2 `isRelease()` 单点失效 → 降级 HTTP 内网 + 击穿正式版日志闸门 + 放开 mock 门控

```javascript
// config/env.js（两端同构）
function miniEnvVersion() { try { ... } catch (e) { return '' } }   // 探测失败返回空
function isRelease() { return miniEnvVersion() === 'release' }
function resolveApiBase() {
  const ver = miniEnvVersion()
  if (ver === 'release' || (ver === 'trial' && TRIAL_USE_PROD_API)) { /* 校验 HTTPS + 占位符 */ }
  return resolveDevApiBase()      // → http://192.168.1.110:8000/api
}
```

只要 `getAccountInfoSync()` 抛错、低版本不支持、或支付宝返回独有的 `gray`，`isRelease()` 即为 false，同时触发：

- **请求降级**到 `http://192.168.1.110:8000/api`（`env.js:82-84`），HTTPS 与合法域名校验被整体绕过；支付宝 `my.request` 正式/体验版只支持 HTTPS + 白名单，必然 100% 失败。
- **正式版远程日志闸门被击穿**：`app.js:11` `if (!isRelease()) remoteLogger.install()` → 正式版也会执行 `install()`，`logger.js:138-142` 劫持全部 `console.*` 并 POST `/client-logs`，与 `app.js:8-10` 的隐私注释直接矛盾。
- **mock 登录门控失效**：支付宝 `auth.js:113-117`、`:125-127` 的 `!env.isRelease` 条件放行 `mock:simulator`。
- `DEV_USE_LAN=false`（`env.js:29`）形同虚设：非 IDE 一律强制走 LAN（`env.js:82`），与 `环境说明.txt:36` 的说明矛盾。

**修复**：判定改为「非 `develop`/`trial` 一律视为生产」（白名单反转），`''`/未知值 fail-safe 到生产；`reportApi` / `push` / mock 分支各自再做一次环境闸门，不依赖单一 `isRelease()`。

### P0-3 后端 `app_env` 默认 development 放大客户端调试凭证（端到端链条）

客户端确实存在调试后门：`member.js:835-838` 提交 `phone_code:'mock:debug'`（UI 由 `shouldShowDevTips()` 隐藏，但代码仍打包）、支付宝 `auth.js:115/127` 的 `authCode:'mock:simulator'`、`pay.js` 的 `isMockPay()` 识别 `mock_settled/_mock`、两端 `recharge.js` 判 `mock_settled` 直接成功。

**后端并未完全兜住**（详见 §6 Q3/Q10）：`miniprogram_auth.py:32-36` 的 `_allow_explicit_mock_code()` 只判断 `is_development`，`code2session` 在密钥检查**之前**就返回 `wx_dev_/ali_dev_` 稳定身份；`alipay_mini_client.py:315-320` 在默认配置（`app_env=development` + `alipay_aes_key=''`）下用正则从客户端字符串里抓明文手机号当作「官方解密结果」，随后走 `bind_verified_phone(confirm_merge=...)`（**已验证绑定 + 账号合并**）；`wechat_mini_client.py:114-118` 用 code 的 md5 伪造「已验证」手机号。

即：**生产 `APP_ENV=production` 下这些链条被 `is_production`、AES 强制校验和 `startup_checks.py:189-208` 拦住，但任何未显式设置该变量的部署近似「调试后门全开」**。这与全量报告的 P0-1 同源，此处补充了小程序侧的完整利用链。

**修复**：所有 mock 分支统一走 `dev_mode_allowed(mock_flag)` 三重门控（非生产 + `app_debug` + 显式开关）；mock 结果禁止进入 `bind_verified_phone`；客户端删除或硬门控调试凭证。
