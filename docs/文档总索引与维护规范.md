# 项目文档总索引与维护规范

> 最近整理：2026-11-08。此索引用于定位文档与规定维护方式，不替代代码、配置、数据库迁移和 CI 证据。
> 仓库默认主线为 main；功能状态按“已实现且验证 / 已实现待验证 / 设计规划 / 外部阻塞 / 历史归档”标记。

## 1. 权威顺序

出现冲突时按以下顺序核对，不可只选择看起来更新的文档：

1. 当前 main 的实际代码与配置。
2. 数据库：sql/struct.sql canonical schema + backend/alembic/versions/ 迁移链；初始化种子脚本按各自用途执行。
3. 当前 CI workflow、锁文件和测试结果。
4. 现行专题文档：架构、数据库、部署、安全、支付/退款、多门店、外卖和操作手册。
5. 历史审计报告、旧设计方案、提示词和截图说明。

文档不应覆盖代码事实；发现冲突要记录并修订文档或代码，不能静默选择。

## 6. 文档状态定义

| 状态 | 定义 | 必须证据 |
|---|---|---|
| 已实现且验证 | 代码存在且本次对应测试通过 | 路径/commit + 测试命令/结果 |
| 已实现待验证 | 代码存在但关键环境或测试未执行 | 代码路径 + 未验证原因 |
| 设计规划 | 仅有需求、设计或任务 | 设计文档/需求编号 |
| 外部阻塞 | 需要商户凭证、平台审核、现场设备或运维资源 | 阻塞项、责任人、下一步 |
| 历史归档 | 旧审计、旧分支、旧测试快照 | 原始日期/commit，不作为当前结论 |

不得用“已完成”“已支持”“可上线”概括尚未通过真实环境验收的功能。

## 7. 每次代码变更必须同步哪些文档

| 变更类型 | 至少更新 |
|---|---|
| API/权限/租户 | 架构或 API 说明、门店隔离清单、后台手册、问题台账 |
| 数据库模型/迁移 | 数据库设计、迁移说明、种子说明、测试报告 |
| 支付/退款/账本 | 支付对接、退款流程、账务审计、测试报告 |
| Redis/任务/队列 | 架构、部署/故障排查、审计台账、故障测试报告 |
| 前端/小程序 | README、操作/上架/环境说明、构建测试报告 |
| 摄像头/人脸/语音 | 隐私安全、人脸说明、现场验收、运维手册 |
| 依赖升级 | manifest + lockfile、依赖审计、CI 和兼容性记录 |
| 发布/部署 | 部署说明、配置清单、变更记录、回滚和恢复证据 |

## 8. 文档质量门禁

- 所有文档 UTF-8；中文文档用简体中文；命令标注 PowerShell/Bash。
- 不得出现真实密码、JWT、AppSecret、私钥、AES Key、摄像头凭据或有效访问 token。
- 不写死会过期的“最新版本”；记录核验日期和官方来源。
- 不使用本机绝对路径作为唯一操作指引。
- 所有测试数字必须绑定 commit、平台、运行时、命令和执行日期。
- 历史报告不覆盖当前状态；未执行项目标记待验证。
- 文档内的路径、表名、环境变量、权限码必须能在当前仓库找到。
- 删除/重命名文档时同步更新 README、索引和交叉链接。
