# 五条铁律（任何时候不得违反）

4. **合规铁律**：禁用"第一家/唯一/首创/最好吃/NO.1/顶级"等无法证实的表述

   只能用可证实的事实：「每日现炖肥肠」「血旺当日鲜供」「可做清汤/微辣」。
5. **价格与储值铁律**：价格比较的"原价"不得高于本店前七日内最低成交价，不得先提价再打折；
   储值必须可查余额、可退、七日无理由退本金，不得写"最终解释权归本店""不退不换""到期清零"。

- 拿不准就判 WARN 并说明风险，不要为了通过而放行

# 附：调用建议（工程实现）

## 1. 提示词与数据库的绑定关系

| 提示词 | 依赖的表 | 触发时机 |
|---|---|---|
| P0 System | `shop_config` | 每次会话初始化 |
| P1 每日动作 | `promo_rule` `promo_festival` `crm_customer` `crm_order` `promo_coupon` | 每日 06:00 定时任务 |
| P2 节日活动 | `promo_festival` `promo_activity` | 节日前 14 天自动触发 |
| P3 文案 | `promo_activity` `shop_config` | 手动或活动创建时 |
| P4 会员关怀 | `crm_customer` `crm_customer_tag` | 流失预警任务 / 生日 / 升级 |
| P5 公益 | `crm_tag` `promo_rule` | 手动 |
| P6 复盘 | 全部 | 每月 1 日 |
| P7 成本核算 | `product_cost` `promo_rule` | 创建规则时校验 |
| P8 漏斗 | `marketing_channel` `crm_customer` | 每周一 |
| P9 情报 | 无（人工输入） | 手动 |

## 2. 关键实现细节

- **变量填充**：所有 `{{var}}` 由后端组装成 dict 后做字符串替换，缺失变量填 `"（暂无数据）"`，不要让占位符泄漏到模型输入
- **成本硬校验**：P7 的输出在入库前，用 Python 再算一遍，AI 算错的成本必须拦下来
- **规则冲突校验**：新规则入库前检查 `mutex_group` 冲突和优先级
- **话术留痕**：P4 生成的话术发给顾客前，存一份到 `crm_message_log`，避免重复打扰同一会员
- **温度参数**：P3 文案类 temperature=0.8，其余 0.3–0.4
- **降级方案**：AI 不可用时，P1 退化为规则引擎直接查 `promo_rule` 表输出，保证每日动作不断档

## 3. 最小可用版本（MVP）建议

先做这三个，就能跑起来：
1. **P1 每日营销动作**（最高频，老板每天都要）
2. **P4 会员关怀话术**（黏性核心，直接复用 `preferences` 字段）
3. **P2 节日活动生成**（节日是最确定的流量窗口）

其余提示词等这三条跑顺了再加。
