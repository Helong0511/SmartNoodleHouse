# 数据库说明

## 权威来源

| 产物 | 说明 |
|------|------|
| `sql/struct.sql` | **结构基线来源**：含 Alembic `CANONICAL SCHEMA` 段；禁止直接对已有数据库执行，结构创建/升级统一走 Alembic |
| `sql/data_sys.sql` | 系统种子来源；包含多表 `TRUNCATE`，只允许在确认全新空库时按显式确认流程执行一次 |
| `sql/data_custom.sql` | 门店经营种子；仅限全新数据库首次初始化，禁止对已有库重复导入 |
| `sql/data_test.sql` | **仅本地测试数据**，禁止写入生产 |
| `backend/alembic/versions/` | 版本化迁移；`upgrade head` 从空库可达当前 schema |

Alembic：

1. **0001_baseline** — 只读取 `sql/struct.sql` 的 `CANONICAL SCHEMA` 分段，不执行删库、授权和种子段。
2. **0002_p0_hardening** — 对旧库补丁：`orders.operator_id`、幂等键注释、webhook / 退款重试列、`financial_ledger`、`point_ledger`。
3. **0003 ~ 0006** — 欢迎券 UNIQUE、班次唯一 OPEN、券 `status_reason`、`print_jobs`。
4. **0007_prod_indexes** — 订单/支付/退款/账本/券复合索引。
5. **0008+** — 券门店、地理/规格范围、身份安全、外卖、台账幂等、口味推荐、三方对齐、折扣精度、分类时段、门店 Logo 等。

校验脚本：`python scripts/验证数据库.py`（关键表、`alembic_version`、UNIQUE / FK、P0 列、生产索引）。

## 模块概览

- **RBAC**：`roles` / `permissions` / `role_permissions` / `users` / `operation_logs`
- **门店**：`stores` / `tables` / `store_settings`
- **会员营销**：`customers`、`member_levels`、`coupon_templates`、`customer_coupons`、渠道账号表、`point_ledger`、`point_exchange_options`
- **订单支付**：`orders`（含 `operator_id`、`idempotency_key`）、明细与规格快照、`payments` / `payment_refunds`、班次与 POS 退款申请、状态历史、回调回执
- **异步接入**：`webhook_inbox`（含 `attempt_count` / `next_retry_at` / 锁字段）
- **财务**：`financial_ledger`（SALE / REFUND / ADJUSTMENT）
- **外卖**：映射、扩展单、平台绑定、退款与回调日志
- **迎宾**：摄像头、客流、人脸档案、欢迎日志
- **配置**：`system_settings`

## 关键约束（生产勿删）

- `orders.uk_idempotency`：下单幂等（允许多个 `NULL`）
- `orders.fk_orders_operator` → `users.id`
- `webhook_inbox.uk_webhook_event`：`(channel, event_id)`
- `payments` / `payment_refunds` 业务单号唯一；退款可选 `uk_refund_idempotency`
- 门店、订单、支付相关 FK 保证跨表一致性

## 初始化与升级安全规则

- **全新数据库**：先创建空数据库，再在 `backend/` 中执行 `alembic upgrade head`；`0001_baseline` 会从 `sql/struct.sql` 读取标记的 canonical schema 分段。
- **已有数据库（包括生产营业库）**：先备份并在隔离副本完成恢复演练，再执行 `alembic upgrade head`。不得运行初始化 SQL 代替迁移。
- `sql/struct.sql` 包含破坏性重建段，**禁止直接执行** `mysql < sql/struct.sql`。
- `sql/data_sys.sql` 含多表 `TRUNCATE`，仅全新空库且经人工确认时可使用仓库规定的 `SMART_NOODLE_FRESH_INSTALL_CONFIRM=YES` 连接级保护执行一次；绝不可对已有库或生产营业库执行。
- `sql/data_custom.sql` 只在全新数据库首次初始化时导入，禁止重复灌入。
- 角色/权限等可重复种子优先使用本节列出的 Python seed 脚本；`sql/data_test.sql` 永远只用于本地测试。

历史手工补丁保存在 `sql/tools/`，仅供追溯；新环境和已有库的结构升级统一使用 Alembic，不要再手工执行已并入迁移链的 tools 脚本。
