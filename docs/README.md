**[通用项目审计与上线防错标准](engineering/通用项目审计与上线防错标准.md)** 是从本项目真实审查问题中提炼的通用规范，可作为其他项目立项、架构评审、代码审查、CI、上线验收和事故复盘的基础清单。使用时需按目标项目技术栈、业务风险和监管要求裁剪，不能把本项目的具体实现照搬为所有项目的唯一方案。

## 6. 文档状态约定

- **现行说明**：描述当前实现；必须能在当前 main 代码/配置中找到依据。
- **规划/方案**：描述待建设能力；明确标注计划、待实现、待验收，不得写成已上线。
- **审计报告**：保留发现时的 commit、证据、触发前提与审查边界。
- **修复台账**：只有代码已合并、测试通过且外部条件完成后才能标记关闭。
- **历史报告**：保留历史事实，不能删除失败记录或将历史通过数冒充当前结果。

## 7. 文档更新触发条件

修改 API、环境变量、数据库表/迁移、权限、支付、外部回调、Redis key/锁、前端身份、平台隐私 API、部署脚本、依赖锁文件或 CI 时，必须同步更新对应文档和 README 索引。PR 必须检查链接、命令、路径、版本和字符集；禁止提交密钥、真实令牌和个人数据。
