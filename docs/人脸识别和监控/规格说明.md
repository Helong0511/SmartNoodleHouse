# 连锁门店本地化视频监控与智能人脸识别系统 — 规格说明

## 问题

当前人脸识别系统将所有摄像头视频流汇聚到中心服务器处理，存在以下问题：
- 多路摄像头视频上传占用大量服务器带宽
- 人脸 embedding 提取（insightface）在中心服务器运行，门店越多算力压力越大
- 缺少连续录像存储能力
- 未匹配人脸无法在后台集中管理和标识

## 用户与目标

**用户：**
- 门店运营人员：通过门店本地电脑完成监控录像和人脸识别
- 总部管理员：在中央后台查看未匹配人脸、添加标识、管理迎宾

**目标：**
- 在每个门店部署专用电脑，本地完成视频采集、录像存储、人脸识别
- 仅将未匹配的人脸截图（含元数据）推送到中央服务器，大幅降低带宽和算力需求
- 中央后台提供未匹配人脸的集中查看与标识功能
- 已标识顾客再次到店时，门店电脑本地播报欢迎语音

## 非目标

- 不在本阶段改造现有会员小程序的人脸注册流程（仍走小程序授权）
- 不在本阶段实现跨门店人脸特征同步（各门店独立缓存）
- 不在本阶段实现录像的远程回放（仅本地存储，后续可扩展）

## 功能需求

### FR-1 门店边缘代理（Edge Agent）

门店电脑运行独立代理进程，负责：
1. 连接并管理本门店所有摄像头（支持 RTSP/USB，单路及多路）
2. 实时视频录制到本地硬盘（按时间切片，自动清理过期文件）
3. 实时人脸检测与特征提取（复用 insightface）
4. 与本地缓存的已标识人脸特征库匹配
5. 匹配成功 → 本地 TTS 播报欢迎语
6. 匹配失败 → 推送人脸截图到中央服务器（带去重冷却）
7. 定期从中央服务器同步已标识人脸特征库（增量）

### FR-2 中央服务器 — 未匹配人脸接收

- API `POST /api/edge/unknown-face`：接收边缘推送的未匹配人脸
  - 入参：`store_id`、`camera_id`、`timestamp`、`face_image`（JPEG base64 或 multipart）、`embedding`（可选，边缘提取的 512 维向量）
  - 鉴权：门店级 Edge API Key（Header `X-Edge-Api-Key`）
  - 存入库表 `unknown_faces`，状态为 `unlabeled`
- 边缘代理通过独立的 API Key 鉴权，不使用员工 JWT

### FR-3 中央服务器 — 已标识人脸特征库同步

- API `GET /api/edge/face-profiles?since=<timestamp>`：边缘拉取已标识人脸特征
  - 返回：已标识（labeled）的人脸记录，含 `face_id`、`label` 或 `customer_id`、加密特征向量、`updated_at`
  - 边缘本地缓存用于匹配，TTS 播报使用 `label` 或顾客昵称
- 支持增量同步（since 参数），减少传输量

### FR-4 中央服务器 — 未匹配人脸管理后台

- API `GET /api/admin/unknown-faces`：分页查看未匹配人脸列表
  - 筛选：门店、状态（unlabeled/labeled/ignored）、时间范围
- API `PATCH /api/admin/unknown-faces/{id}`：标识人脸
  - 设置 `label`（自由文本，如"王老师"）或 `customer_id`（关联已有顾客）
  - 标识后状态变为 `labeled`，该人脸特征写入 `face_profiles`（供边缘同步）
- API `DELETE /api/admin/unknown-faces/{id}`：忽略/删除未匹配人脸

### FR-5 中央服务器 — 已标识顾客迎宾事件

- 边缘匹配成功后，可选推送迎宾事件到中央服务器（用于日志统计）
- 中央服务器不负责 TTS 播放，TTS 由门店电脑本地完成

### FR-6 系统集成与安全

- 边缘代理与中央服务器通信使用 HTTPS + 门店级 API Key
- 人脸特征向量在传输和存储中加密（复用 `FACE_ENCRYPTION_KEY`）
- 未匹配人脸图像存储遵循隐私合规（设置保留期限，默认 30 天后自动清理）
- 边缘代理支持离线运行：断网时继续录像和识别，未匹配事件缓存到本地 SQLite，恢复后批量上报

## 非功能需求

### NFR-1 性能
- 边缘代理单店支持 4 路摄像头同时采集 + 识别（3 fps/路）
- 人脸匹配延迟 < 200ms（本地缓存特征库 < 1000 人）
- 未匹配人脸推送去重冷却：同一摄像头 60 秒内同一人脸不重复推送

### NFR-2 可靠性
- 摄像头断线自动重连（指数退避，上限 30s）
- 录像文件损坏不影响采集进程
- 中央服务器不可达时，未匹配事件本地缓存（最多 1000 条），恢复后上报

### NFR-3 存储
- 录像按 30 分钟切片，MP4 格式（H.264）
- 保留天数可配置（默认 7 天），自动清理过期文件
- 未匹配人脸图像存储在服务器 `uploads/unknown_faces/`，保留 30 天

### NFR-4 安全
- 门店 API Key 每个门店独立，存储在门店电脑本地配置文件（权限 600）
- 人脸图像上传限制单张 < 2MB
- API 速率限制：边缘推送 60 次/分钟

## 约束与假设

- 门店电脑运行 Python 3.11+，已安装 OpenCV + insightface
- 门店电脑有足够磁盘空间（建议 ≥ 500GB）
- 摄像头支持 RTSP 协议或 USB 直连
- 中央服务器已有 `FACE_ENCRYPTION_KEY` 配置
- 现有 `face_extractor.py` 可在边缘环境直接运行（依赖 insightface）

## 开放问题

1. 已标识人脸的特征向量由谁提取？
   - **方案 A**：边缘推送未匹配人脸时同时上传 embedding，管理员标识时直接使用该 embedding
   - **方案 B**：管理员标识时，中央服务器重新从人脸图像提取 embedding
   - **决策**：采用方案 A（边缘已提取，复用节省算力），但中央服务器保留重新提取的能力作为兜底
