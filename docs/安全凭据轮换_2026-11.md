# 2026-11 凭据泄露应急轮换说明

> **P0：必须处理。** 公开仓库的旧版本曾包含数据库口令、桌台二维码 bearer token 和演示员工密码哈希。当前分支已移除明文口令、移除静态演示账号并为新种子生成随机桌台 token；但这些提交不能清除 Git 历史，也不能自动修改已部署数据库。

## 立即执行

### 1. 轮换数据库账号

先确认应用实际使用的 MySQL 账号及 Host。对 `sql/struct.sql` 中的旧账号，在 MySQL 管理连接中执行：

```sql
ALTER USER 'remote'@'localhost'
  IDENTIFIED BY 'REPLACE_WITH_A_NEW_UNIQUE_STRONG_PASSWORD';
FLUSH PRIVILEGES;
```

- 使用密码管理器生成至少 32 字节随机密码，不要复用旧密码。
- 同步更新所有应用实例、迁移任务、备份任务和运维脚本的数据库连接串。
- 数据库 URL 中的特殊字符必须进行 URL 编码。
- 如果生产环境实际账号/Host 与上例不同，按实际账号修改；不要为了照抄示例而创建新账号。
- 重启应用并验证数据库连接、读写和后台任务后，再撤销旧账号或旧凭据。

### 2. 轮换已公开的桌台二维码 token

先备份数据库，再由有权限的 DBA 人工审核并执行：

```bash
mysql --defaults-extra-file=/secure/path/mysql-admin.cnf smart_noodle_house \
  < sql/security_rotate_legacy_seed_credentials.sql
```

该脚本只针对旧种子中的 SH01 门店 01/02/03 桌：
- 重新生成随机 token；
- 清空旧微信/支付宝二维码图片 URL；
- 使旧二维码失效。

执行后进入后台重新打印并张贴桌台二维码。若实际门店号或桌号不同，先审核并调整脚本范围，不能直接扩大范围运行。

### 3. 处理旧演示员工账号

上述 SQL 脚本会禁用旧种子账号并递增 token_version，使现有登录令牌失效。之后通过管理员初始化流程或后台创建新账号，为每位员工分配独立强密码。不要重新启用旧账号，也不要把演示密码写回 SQL。

新安装时，`sql/data_custom.sql` 不再插入固定员工账号；管理员应按 `docs/部署说明.md` 的初始化流程设置首个管理员密码。

## Git 历史清理

当前文件修正只影响最新树。旧口令、旧 QR token 和密码哈希仍可能存在于公开 Git commit、fork、缓存和已 clone 的副本中。

在凭据轮换完成后，仓库管理员应：
1. 通知协作者暂停 push，并备份仓库与所有分支/tag。
2. 使用 `git filter-repo` 从所有受影响分支和 tag 的历史中清除相关 SQL 行/旧凭据。
3. 强制更新远端 refs，并清理 GitHub PR refs（按 GitHub 支持流程处理）。
4. 通知所有 clone/fork 持有人重新 clone；旧对象可能仍保留在本地或 fork。
5. 再运行凭据扫描，并确认所有生产凭据已轮换。

**不要把历史重写当作凭据轮换的替代品。** 即使历史清理完成，已经泄露的口令和 bearer token 仍必须视为永久泄露。

## 当前仓库修复

- `sql/struct.sql`：删除硬编码数据库口令，改为显式占位符。
- `.env.example`、`.env.development.example`、`.env.production.example`：将示例数据库/Redis URL 和密钥改为占位符。
- `sql/data_custom.sql`：移除固定演示员工账号；新建示例桌台时使用数据库 UUID 生成 token，不再写入静态二维码 URL。
- `sql/security_rotate_legacy_seed_credentials.sql`：提供仅供 DBA 审核后手动执行的旧数据轮换脚本。
