# 安全说明

仓库历史中曾出现过微信 AppSecret / 支付宝应用私钥 / AES Key，一律视为已泄露，上线前必须在各平台控制台轮换。

## 要求

- 真实密钥只放在本地 `.env` / `.env.development` / `.env.production`（已加入 `.gitignore`），勿写入示例文件、脚本、文档或测试。
- 示例与文档仅使用明显虚假占位符（如 `wx_REPLACE_WITH_YOUR_APPID`、`replace_with_wechat_app_secret_not_real`、`2021000000000000`）。
- 轮换范围至少包括：微信小程序 AppSecret、支付宝应用私钥与对应公钥、接口内容加密 AES Key，以及曾入库的 JWT / 人脸加密等对称密钥（如适用）。

## 密钥轮换提醒（生产运维）

建议建立定期轮换与离职即时轮换机制，至少覆盖：

| 类别 | 示例配置项（名称） | 轮换后动作 |
|------|-------------------|------------|
| 应用鉴权 | `JWT_SECRET` | 全员重新登录；可递增用户 `token_version` 使旧令牌失效 |
| 人脸特征 | `FACE_ENCRYPTION_KEY` | 更换后旧密文可能无法解密，需按迁移方案重采或重加密 |
| 微信 | AppSecret、商户 APIv3 Key、商户私钥 | 同步更新 `.env` 与平台证书；验证支付 / 退款回调 |
| 支付宝 | 应用私钥、支付宝公钥、AES Key | 更新后回归授权手机号与支付回调 |
| 外卖 | 美团 / 饿了么 app_secret、token | 重新授权门店绑定 |
| 屏端 / 反代 | `DISPLAY_SCREEN_TOKEN`、`TRUSTED_PROXY_IPS` | 更新叫号屏 URL；确认反代 IP 白名单无误 |

轮换操作不要把新密钥写入 Git、工单附件或聊天记录；审计谁有权读生产 `.env`。

## 运行时加固

- 生产关闭所有 `ALLOW_*_MOCK`。
- `PROCESS_ROLE`：`auto`/`leader` 经 Redis 锁选举，避免多 worker 重复调度；`worker` 永不调度。
- JWT：签发带 `aud`（`JWT_AUDIENCE`）；顾客令牌独立 TTL（`CUSTOMER_JWT_EXPIRE_MINUTES`）。
- 人脸/业务密钥：Fernet 材料经 SHA256 派生；解密兼容历史「截断补零」密文。
- `TRUSTED_PROXY_IPS`：仅信任反代 peer，防止伪造客户端 IP。
- Webhook：验签 +（建议）出口 IP 白名单。
- 上传与回调接口限流；管理端敏感操作写 `operation_logs`。

## 2026-11-08 全量审查补充（上线阻断，未代表已修复）

全量审查报告基于 main @ 442beb4761b29f5b415830e91e06c97241f74ef3，发现以下需按 P0 优先处理的事项：

1. **APP_ENV fail-closed**：当前审查发现 APP_ENV 默认 development，未知值可导致非生产安全分支，且校验只在 lifespan 执行。应改为显式 opt-in 开发、未知值按生产策略，并在应用创建阶段校验；支付 mock、验签跳过、mock 登录等旁路必须各自防护。
2. **httpx 日志泄露**：httpx INFO 请求日志曾将微信 token URL 的 query 中 secret 明文写入日志。应降低 httpx 日志级别并对 URL/query/header 通用脱敏；已写入日志或 Git 历史的凭据必须吊销/轮换，不得只删除日志。
3. **异常回显与密钥片段**：错误响应不得回显异常原文、数据库错误或 JWT/支付密钥首尾片段，所有环境都应统一安全输出。
4. **小程序发布态**：release 配置必须有真实 HTTPS API 域名，环境探测异常不得降级到开发 HTTP 地址；正式配置验证不能导致模块加载时白屏。
5. **凭据与日志扫描**：发布前扫描源码、文档、日志归档、工单导出与构建产物；只输出命中类型和文件位置，不输出密钥值。

P0 以外还包括 WebSocket 默认拒绝、空令牌拒绝、令牌与门店绑定、请求体和分页限制、Redis 限流故障策略、异步任务与 DB 事务边界等。逐条证据见 [FULL_CODE_REVIEW_2026-11-08.md](audit/FULL_CODE_REVIEW_2026-11-08.md)。

**状态规则：**本节是审查发现和修复要求，不是修复完成声明。只有对应代码提交、测试结果、密钥轮换凭据和生产验证记录齐备后，才可在审计台账中关闭。
