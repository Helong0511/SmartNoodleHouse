# 通用软件项目审计与上线质量防错标准

> 文档性质：跨项目可复用的工程规范、代码审查清单、上线门禁与复盘模板。
> 来源基线：SmartNoodleHouse 全量代码审查报告（2026-11-08，main @ 442beb4761b29f5b415830e91e06c97241f74ef3）。
> 适用范围：Web / API / 小程序 / 移动端 / 桌面端 / SaaS / 多租户 / 支付交易 / IoT / AI 服务。
> 核心原则：先证明安全与正确，再证明可用与性能；先验证真实行为，再写“已完成”；不以增加代码量或测试数量作为质量目标。

---

## 1. 使用规则

1. 每个新项目在需求、架构、开发、测试、发布、运维各阶段都应执行本标准。
2. 每条检查项标记为：通过、失败、不适用（说明理由）、待外部验证。不得把未验证写成通过。
3. 每个缺陷必须有唯一编号、严重级别、证据位置、触发前提、业务影响、修复方案、回归测试、责任人和状态。
4. 安全、支付、权限、数据迁移、个人信息和破坏性操作必须 fail-closed；不得用 warning、默认值或“通常不会发生”替代安全门禁。
5. “已修复”必须关联代码提交和可重复测试证据；CI 绿灯不代表真实第三方平台、生产数据库或部署环境已验收。
6. 依赖升级必须核对官方支持矩阵、运行环境、锁文件、传递依赖、安装脚本、许可证与漏洞，并执行回归；禁止盲目升级到最大版本。
7. 文档必须与代码、配置、数据库迁移、CI、部署脚本同步；文档命令应在隔离环境实测。
8. 历史发现与当前状态分开记录。历史问题即使已修复也保留原因和防复发规则；未验证的修复不得关闭。

## 2. 缺陷分级与发布门禁

| 等级 | 定义 | 示例 | 发布策略 |
|---|---|---|---|
| P0 阻断 | 可造成资金/数据/权限重大损失、凭据泄露、生产不可启动或不可恢复 | 零元支付旁路、跨租户越权、真实密钥泄露、部署命令删库、正式版白屏 | 必须修复并验证，禁止发布 |
| P1 高危 | 核心业务在常见或可控条件下错误，可能造成账务、订单、库存、隐私或服务中断 | 回调 2xx 丢单、金额不比对、重复退款、鉴权默认放行 | 原则上发布阻断 |
| P2 中危 | 可靠性、性能、边界条件或一致性明显不足 | Redis 降级不一致、分页无上限、请求竞态、状态清理不完整 | 明确计划、监控与负责人 |
| P3 改进 | 可维护性、体验、死代码、重复实现或文档问题 | 未使用依赖、注释缺失、重复页面、过期说明 | 纳入迭代，不得掩盖 P0/P1 |

发布前检查：
- [ ] P0 = 0。
- [ ] P1 = 0；任何例外须书面风险接受，不允许资金、身份、隐私、破坏性数据操作例外。
- [ ] 关键测试通过；失败、跳过、未运行分别说明。
- [ ] 数据迁移在生产同版本数据库演练，验证前滚/回滚策略。
- [ ] 备份完成且恢复演练通过。
- [ ] 真实密钥、平台沙箱、域名、证书、告警和回滚责任人已确认。
- [ ] README、部署指南、环境模板、API/数据库说明与实际代码一致。

## 3. 配置、环境与启动安全

### 3.1 环境识别必须 fail-closed
- 开发模式必须显式 opt-in；未知环境值、拼写错误、空值一律按生产安全策略处理。
- 生产校验不能只依赖 lifespan、启动脚本或人工命令；应用工厂/入口应在路由开放前完成关键校验。
- ASGI 关闭 lifespan 或改变 worker 启动方式，也不得绕过关键配置校验。
- mock 支付、跳过验签、调试登录、模拟退款、测试用户等关键旁路自身必须检查生产环境，不可只依赖全局校验。
- 用部署事实交叉校验：真实商户号、非回环数据库、正式小程序环境、生产域名出现时，禁止开发模式或 mock。
- 未知配置值应拒绝启动，而不是静默回退 development。

### 3.2 配置清单
- [ ] 每个环境变量有类型、默认值、允许范围、敏感级别和来源说明。
- [ ] 生产必填项缺失、占位符、弱口令、无效 URL、错误算法、非法 CORS、回环公网配置时启动失败。
- [ ] JWT 算法允许列表与签发/验证实现、密钥类型、部署文档一致。
- [ ] 数据库、Redis、对象存储、消息队列、支付渠道分别验证连接和权限。
- [ ] 示例配置只放虚假占位符。
- [ ] .env、证书、私钥、备份、日志、上传目录、构建产物有正确 ignore / ACL / 生命周期策略。

## 4. 凭据、日志与个人信息

- [ ] 禁止记录完整 URL query、Authorization、Cookie、AppSecret、API Key、签名、手机号、人脸特征和支付敏感字段。
- [ ] 同时检查业务 logger、HTTP 客户端、SQL 驱动、SDK、代理、异常追踪和访问日志；尤其注意 GET query 被第三方库 INFO 完整输出。
- [ ] 建立日志字段 allowlist 或通用脱敏 filter；覆盖敏感键大小写、别名、嵌套 JSON、URL 编码。
- [ ] 生产日志级别有基线；不得通过全局 DEBUG/INFO 泄露凭据。
- [ ] 使用假密钥样本测试脱敏；历史日志扫描、封存或安全删除。
- [ ] 密钥进入日志、Git 历史、工单、截图或聊天即视为泄露：立即吊销/轮换，不能只删除文件。
- [ ] 轮换后验证新凭据有效、旧凭据失效，并检查服务、回调、证书、密文迁移和缓存。
- [ ] PII 采集前取得明确同意；撤回、删除、访问控制、保留期限与审计可验证。
- [ ] 日志、指标、错误响应不回显异常原文、SQL、主机名、账号、密钥片段或个人数据。

## 5. 身份认证、授权与多租户

- [ ] 员工、顾客、服务账号、临时票据使用独立 token type / audience / issuer / TTL / 权限范围。
- [ ] token 校验包含签名、算法白名单、过期、签发时间、受众、签发者、用途、版本撤销；客户端 extra 不得覆盖保留 claims。
- [ ] 所有对象级 API 同时验证身份、权限和资源归属；不能只在列表接口过滤。
- [ ] tenant/store/workspace ID 由服务端身份上下文绑定；客户端值只是请求意图，不是授权依据。
- [ ] 查询、更新、删除、导出、WebSocket、文件下载、异步任务、缓存键、幂等键全部纳入租户隔离。
- [ ] 新增 API 默认拒绝；公开接口通过显式白名单开放。
- [ ] 空 token、缺失 secret、未配置密码、缺失 store_id 一律拒绝敏感访问。
- [ ] 比较令牌/签名使用恒定时间比较；短期凭证有过期、范围、重放保护。
- [ ] Redis 故障时认证限流不得静默失效；按路径 fail-closed 或采用经评审的可靠兜底。

## 6. 资金、订单、库存与交易一致性

### 6.1 服务端权威
- [ ] 价格、折扣、税、运费、优惠资格、库存、应付金额由服务端重算；客户端金额、单价、折扣率、活动 ID 不可信。
- [ ] 客户端提交优惠规则/活动 ID 时，服务端完整校验有效期、星期、时段、门店、餐品、分类、身份、次数、限额、费率边界。
- [ ] 金额使用 Decimal/最小货币单位；舍入、抹零、退款、分笔支付明确账务科目和订单总额同步规则。
- [ ] 渠道金额、币种、商户号、应用号、原交易号、订单号逐项匹配；关键字段缺失即拒绝确认。
- [ ] 金额解析失败、查单超时、状态未知时不得标记成功或关闭订单；进入 UNKNOWN/PENDING 并重试、对账。
- [ ] 财务分录失败必须阻止资金确认或通过事务 outbox 保证一致；不能只记录日志继续。
- [ ] 幂等命中时比对所有业务参数；同 key 不同请求返回冲突。
- [ ] 资金状态使用明确状态机；禁止任意 API 直接写 PAID/REFUNDED/CLOSED。
- [ ] 退款按订单、支付单和渠道退款单锁定，校验剩余可退金额，防重复/超额/跨单退款。
- [ ] 免费单/秒杀/赠品也要有一致支付状态、Payment 记录、财务科目和副作用队列。
- [ ] 关单前确认渠道侧未支付；查单失败保持待确认，不得推测未支付。
- [ ] Outbox/Inbox handler 幂等、可重试、可回收 stale processing；外部副作用需平台幂等键或主动查单。

### 6.2 库存与优惠并发
- [ ] 库存扣减采用 DB 原子条件更新（stock >= qty），不能先读再写。
- [ ] 优惠券/秒杀名额采用原子扣减、唯一约束、事务和幂等键；Redis 锁不能替代数据库最终约束。
- [ ] 并发压测覆盖超卖、重复领取、重复回调、重复退款、同一幂等键不同 payload。
- [ ] 死锁、锁超时、连接中断有安全重试边界；重试前确认事务是否已提交。

## 7. Webhook、消息与 WebSocket

- [ ] Webhook 先验签，再校验商户/应用/金额/订单/时间戳/nonce，最后幂等落库。
- [ ] 回调先持久化 inbox，业务处理异步重试；只有真正持久化并确认接受的事件才能返回成功 2xx。
- [ ] 可重试错误返回平台约定的非 2xx；不可重试错误记录审计并按平台契约返回明确 4xx。禁止 catch-all 后统一返回 200。
- [ ] WebSocket 默认拒绝；仅显式公开频道白名单可匿名。逐频道校验 token、角色、租户、资源归属和配额。
- [ ] kiosk/display 令牌必须非空、恒定时间比较、与 tenant/store 绑定；长期秘密尽量不放 query。
- [ ] 顾客推送按 customer/order/session 设计授权路由；不能连接成功却静默不推送。
- [ ] 断线重连、卸载清理、重复订阅、轮询兜底和跨 worker Pub/Sub 都要测试。

## 8. Redis 与分布式系统韧性

- [ ] 分类 Redis key：缓存、限流计数、幂等、锁、Leader、fencing token、挑战票据、会话、消息。
- [ ] 不同语义不能共用不适合的 eviction / TTL；锁、凭证、幂等和安全状态不得被 LRU 随机淘汰。
- [ ] 明确 maxmemory、noeviction、持久化、备份、监控、连接上限、网络隔离和认证。
- [ ] 缓存击穿：热点 key 使用 single-flight/互斥重建、逻辑过期或请求合并；锁有 token、TTL、原子续期/释放。
- [ ] 缓存穿透：参数校验、短 TTL 负缓存；布隆过滤器只作优化，不能缓存错误权限判断。
- [ ] 缓存雪崩：TTL 随机抖动、分批预热、限流、熔断、分级降级。
- [ ] 缓存与 DB 双写定义一致性策略；更新/删除顺序、版本号或 outbox 选择需说明边界。
- [ ] Redis 故障逐路径定义 fail-open / fail-closed：认证、支付、限量活动、回调、分布式锁通常 fail-closed；普通只读缓存可回源 DB。
- [ ] Redis 命令有超时、连接池上限、错误指标、恢复策略；禁止无界重试。
- [ ] 分布式锁使用唯一 owner token + Lua compare-and-delete/renew；关键写操作另用 DB 唯一约束/行锁/fencing 防过期持锁者写入。
- [ ] Leader 任务有租约、fencing、故障接管和重复执行幂等。
- [ ] 注入 maxmemory OOM、主从切换、网络分区、重启丢数据、锁过期、高并发缓存失效故障。

## 9. API、输入与异常处理

- [ ] 输入有长度、范围、类型、枚举、数量、嵌套深度限制；分页 page_size 有上限。
- [ ] 全局请求体限制与网关限制一致；上传限制大小、类型、图片解压尺寸。
- [ ] 登录密码、批量 items、筛选表达式、正则、JSON 深度防 CPU/内存耗尽。
- [ ] 外部 URL 校验协议、DNS/IP、重定向、内网/metadata 地址和端口，防 SSRF。
- [ ] 错误响应只返回稳定错误码和安全消息；堆栈、SQL、内部 host、密钥片段只进脱敏内部日志。
- [ ] DB session 的 commit/rollback 边界显式清晰；依赖层不应无条件自动提交。
- [ ] except Exception 不可静默 pass；容错时必须 rollback、指标告警、记录关联 ID 并说明一致性。
- [ ] 异步函数不得在事件循环执行阻塞文件、CPU、加密或同步网络操作。
- [ ] 任务取消不能被 BaseException 吞掉；关闭连接、后台任务、订阅与线程。

## 10. 前端、小程序和多端差异

- [ ] 员工/顾客 token 不按 URL path 猜测；请求客户端显式标记 token 类型。
- [ ] 401/403、退出登录、切换门店时清理对应身份、缓存、购物车、桌台上下文。
- [ ] localStorage/sessionStorage 视为不可信；JSON.parse 做异常处理，金额不在客户端作为权威值。
- [ ] 异步请求加 AbortController/请求序号/串行化，防旧响应覆盖新状态；卸载时阻止 WebSocket 自动重连。
- [ ] redirect URL/scheme 做协议与域名白名单。
- [ ] 不将长期 token 放 URL、Referer、剪贴板、分析事件或访问日志。
- [ ] 微信与支付宝 API 不可假设同名同义；核对官方 API、隐私授权生命周期、手机号授权、支付参数和基础库版本。
- [ ] 两端共享业务逻辑采用公共核心 + 平台适配器；双端独立打包，CI 做 parity/diff 检查。
- [ ] mock/debug/mock_settled 正式构建与后端双重禁用；客户端标志不可作为完成动作或授权依据。
- [ ] release 环境探测失败必须 fail-safe 到正式配置或明确阻断，不能回退 HTTP 内网地址。
- [ ] 正式 API URL 不允许占位符；校验不应在模块顶层异常导致白屏。
- [ ] 隐私政策、平台隐私 API、授权前采集限制须真机正式基础库验证。

## 11. 数据库、迁移与破坏性操作

- [ ] 明确唯一 schema source of truth：迁移系统或 canonical DDL，不允许多个定义漂移。
- [ ] 每个迁移有 upgrade、必要 downgrade 策略、锁表评估、数据回填、幂等性和耗时估计。
- [ ] 生产升级只允许迁移命令；初始化脚本、测试种子、DROP DATABASE、TRUNCATE、全表 DELETE 必须隔离。
- [ ] README 不得把破坏性初始化命令放在生产部署可复制步骤中；分离全新空库与已有生产库。
- [ ] 初始化脚本默认拒绝生产；破坏操作需要确认标志、目标库白名单、备份与二次确认。
- [ ] 外键、唯一约束、检查约束、索引与 ORM 模型一致；不能只在 SQLite 测试通过。
- [ ] 字符集统一 utf8mb4；连接、DDL、CSV、日志、Windows/CI 输出验证中文不乱码。
- [ ] 备份必须验证可恢复；文件存在不等于恢复能力已验证。
- [ ] 数据删除/归档遵守 FK、审计、保留期限和恢复要求。

## 12. 依赖、构建与供应链

- [ ] 直接依赖在 manifest 声明；生产/测试/工具依赖分组清楚。
- [ ] 精确锁文件纳入版本控制，CI 用 frozen/locked 安装；安装后检查 lock 未被改写。
- [ ] 从源码引用、动态导入、插件入口、CLI、migration、tests 和构建配置核对依赖使用；删除前全仓搜索。
- [ ] 区分直接重复、传递多版本、平台条件依赖；不能只看包名重复就删除。
- [ ] npm/pip/Cargo audit 与许可证扫描纳入 CI；评估可利用性、运行路径、修复版本与破坏性。
- [ ] 版本升级查官方 release notes、语言/OS 支持矩阵、ABI、平台 wheel、系统库、服务端兼容矩阵。
- [ ] 不运行未经审查的 postinstall/build script；采用最小 allowlist。
- [ ] Rust 使用 cargo metadata --locked、fmt、test、audit、重复依赖树和 cargo-machete；Windows DLL 在 Windows runner 构建并检查产物。
- [ ] 小程序 JS 做语法检查；前端做类型检查、单测、构建和 lockfile consistency。
- [ ] 不以 npm audit fix --force、无差别主版本升级或删除 lockfile 作为漏洞修复。

## 13. CI、测试与验证

- [ ] CI 与开发版本对齐，记录 Node/npm、Python/pip、Rust/Cargo、MySQL、Redis。
- [ ] 单测之外有真实 MySQL（迁移、锁、约束、SQL 方言）、真实 Redis（Lua、连接、故障）、前端构建、小程序语法、Windows/目标 OS 构建。
- [ ] 关键业务覆盖成功、失败、重试、超时、重复、并发、部分成功、崩溃恢复、脏数据和权限边界。
- [ ] mock 符合真实调用次数、返回类型、事务、session、锁和错误语义；不得掩盖业务逻辑错误。
- [ ] 不通过删测试、跳过失败、放宽断言、吞异常、只测 mock 宣称修复。
- [ ] 收集失败、测试失败、测试跳过、未执行、外部阻塞分开统计。
- [ ] 慢 CI 检查卡点、资源等待、网络下载、测试死锁、重试循环。
- [ ] 测试报告包含 commit SHA、命令、环境、执行时间、passed/failed/skipped、失败日志链接。
- [ ] 故障注入 DB/Redis 中断、连接池耗尽、回调重复/乱序、磁盘满、进程 kill、worker 重启、网络分区。

### 16.1 P0（4 组）
1. 生产环境判定单点失效：APP_ENV 默认 development，未知值可能落入非生产；关键校验只在 lifespan 执行。触发时 mock 支付/退款、回调跳过验签、mock 登录、异常回显、密钥片段回显可能同时开放。要求显式 opt-in 开发、未知值按生产、应用创建时校验、关键旁路自带硬断言。
2. httpx INFO 日志泄露微信 AppSecret：HTTP 请求 URL query 被完整记录，仓库日志样本含真实密钥。立即轮换已暴露凭据、脱敏 HTTP 日志、清理/封存日志、增加日志敏感串扫描。
3. 双端小程序正式环境配置风险：正式 API 域名有占位符；环境探测失败可能回退 HTTP 内网地址；模块顶层抛错可导致正式版启动白屏。发布环境 fail-safe、域名校验、延迟请求前检查。
4. 生产部署文档 SQL 破坏性冲突：README 生产步骤指示执行会 DROP DATABASE 的 struct.sql 和 TRUNCATE 系统种子；与“已有库勿执行”警告矛盾。必须分离全新空库初始化与已有生产库 Alembic 升级，并增加备份/确认门禁。

### 16.2 P1（22 条）
资金与订单一致性：
- 客户端可指定 social_rule_id，部分路径绕过日期、时段、次数、餐品和折扣率校验。
- 付款码支付金额回校读取无人写入的 provider_amount，金额核对实际不生效；充值支付缺金额校验。
- 微信回调外层事件 ID 未透传，幂等回执身份为空；退款幂等键包含可变时间字段。
- 非生产财务分录异常只记录日志继续确认支付/退款，可能产生无台账交易。
- 抹零降低 pay_amount 却未同步 order.total_amount，订单可能停留 PARTIAL_PAID。
- 查单/关单异常仍关闭本地支付单，可能与渠道已扣款冲突。
- 充值幂等只校验 customer_id，未校验套餐、门店、金额和赠送额。
- 秒杀免费单直接写 PAID/FREE，但缺 Payment/统一副作用，支付进度与对账状态不一致。
- 退款 SUCCESS 对缺失渠道身份字段采取宽松放行。
- 充值结算幂等守卫使用 AND，崩溃中间态可能重复结算。

API、鉴权与并发：
- 外卖回调 catch-all 后返回 200，可能静默丢单/丢退款。
- WebSocket 使用受保护频道集合；新增未知频道可能默认免鉴权。
- display 频道空令牌条件下有绕过风险，token 未绑定门店且比较非恒定时间。
- 顾客订单 WebSocket 缺少有效 store/customer 投递上下文，可能连接成功但不推送。
- DB 依赖层 yield 后无条件 commit，与路由显式 commit/吞异常组合导致事务边界不清。
- 生产启动校验仅允许 HS256，与实现支持 RS256/EdDSA 不一致。
- 密钥占位符校验未覆盖 FACE/SECRET/S3 等字段。
- 请求体大小限制只覆盖少数 webhook；items 和密码长度限制不足。
- 入侵检测不扫描 JSON body，误把 UA/Referer 纳入攻击特征，startswith 例外可绕过。
- 登录锁定 Redis 异常时直接放行，失败计数异常被吞。

前端与小程序：
- 401 拦截器根据 URL 猜测员工/顾客 token 类型，后台根路径可能误判。
- 支付宝隐私代码照搬微信 API，异步初始化 Promise 被丢弃，授权可能未实际触发。
- 员工/顾客 token 在请求层混用；WebSocket 卸载时 onclose 可能重新连接。
- POS 切门店存在请求竞态。
- 非生产构建可能自行生成 mock login code；小程序 mock_settled/mock 登录门控不严。
- 共享购物车接受客户端 unit_price；人脸 action_completed 由客户端硬编码 true。
