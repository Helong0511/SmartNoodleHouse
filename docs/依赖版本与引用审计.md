## 3. 已核对的版本基线

- Python 运行时：3.11；运行时锁文件位于 `backend/requirements.lock`。
- Python 测试依赖：独立位于 `tests/requirements.txt`，避免把 SQLite 测试驱动混入生产运行时。
- 前端：Node 24、npm 11.19.1；`package-lock.json` 是实际安装依据，禁止只改 `package.json` 而不更新 lock。
- Rust：`Cargo.lock` 中直接依赖包括 aes-gcm 0.10.3、base64 0.22.1、hex 0.4.3、rand 0.8.8、serde 1.0.229、serde_json 1.0.151、uuid 1.26.1、once_cell 1.21.4、proptest 1.11.0、criterion 0.5.1、winres 0.1.12。
- Cargo.lock 出现 rand 0.8/0.9、getrandom 0.2/0.3/0.4、syn 2/3 等多个版本，属于不同传递依赖链的 SemVer 约束结果；不是同一个直接依赖重复声明，不能简单删除其中某一版。
- npm lock 当前 179 个 node_modules 项目，没有发现同名包被解析为多个版本。

## 4. 重复文件与跨端代码

Git 对象树发现 16 组相同内容文件。主要包括：

1. 微信/支付宝小程序共用的购物车定价、客户端配置、日期、取餐、共享购物车、税号工具；
2. 确认订单、商品详情、下单结果页面的同构 JS 逻辑；
3. 部分组件 JSON、页面模板/样式和品牌 Logo。

微信与支付宝必须分别打包，因此相同文件副本有一部分是平台目录隔离导致的合理重复，不应直接删除或用软链接替代。本轮新增 `tests/test_miniprogram_shared_files_parity.py`，对关键共享 JS、组件配置和 Logo 做字节级一致性检查，避免修复只落到其中一端。其他重复样式/模板需结合页面引用关系再决定是否抽取，不能仅因 SHA 相同就贸然删除。

## 5. 自动审计与维护

- `scripts/audit_dependency_references.py`：解析后端 Python AST，检查未声明的第三方导入、同一作用域重复导入、重复依赖声明，并列出动态加载依赖及其原因。
- `scripts/check_requirements_lock.py`：检查运行时依赖清单与锁文件是否对齐。
- CI 增加依赖引用审计、测试依赖统一安装、Rust Cargo.lock/格式/测试。
- Dependabot 每周检查后端 pip、前端 npm、测试 pip、Rust Cargo 和 GitHub Actions 更新。

## 6. 简体中文注释约定

关键业务代码优先使用简体中文解释“为什么这样做”和不可破坏的约束，尤其是：

- 支付验签、退款幂等、库存扣减、订单状态机；
- Redis Lua 原子边界、锁 token/fencing、缓存代际与 Outbox；
- 多门店数据隔离、权限校验和租户范围；
- 人脸数据授权、密钥轮换、活体检测、摄像头播报；
- 微信/支付宝渠道差异、支付回调与重复请求。

不要求给每一行代码加注释，也不重复描述显而易见的语句。注释应与实现同步；行为改变时必须同步更新注释和测试。

## 7. 尚需 CI 证实的事项

- 新版 FastAPI/Pydantic/NumPy/ONNX Runtime 与现有后端测试兼容；
- Python AST 依赖审计没有漏掉的动态/可选依赖；
- 微信/支付宝共享文件一致性测试通过；
- Rust DLL 在 Linux CI 上可锁文件构建并通过单元测试；
- npm 的 Vue/Element Plus/Vite 最新补丁升级必须由 npm 正式重生成 lockfile 后再验收，不允许手工伪造 integrity 或 resolved 信息。
